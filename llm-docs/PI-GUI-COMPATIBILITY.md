# Milestone 0: compatibility proof

Status: **milestone 0 complete as a controlled compatibility/feasibility proof**. All eight approved gates have reconciled evidence, including executed Durable probes. Supported, source-only, unsupported and implementation-deferred boundaries remain explicit below. Rust/demo GUI code remains unchanged; milestone 1 was not started.

## Reproduce

```sh
# Actual installed Pi CLI, fake in-process provider, no GUI/live accounts:
node --test scripts/pi-compat/tests/*.test.mjs
# Include compatibility probes in full repository validation:
PI_GUI_CHECK_COMPAT=1 ./scripts/check.sh
```

Requirements: Linux, Git, `flock`, reviewed Node **v24.13.0** and an installed `@earendil-works/pi-coding-agent` **1.1.0**. The harness locates the package through the resolved `pi` executable, or `PI_GUI_PI_PACKAGE=/absolute/package/directory`. It launches the package's declared CLI entry point with the current Node executable. It rejects version drift and asserts the selected provider/model are the fixture before sending any prompt. No package installation or network dependency resolution runs.

Observed/pinned baseline: Pi **1.1.0**, Node **v24.13.0**, pi-subagents **0.76.1**, pi-web-access **0.37.0**. `build-lock.{mjs,json}` rejects changes to Pi's own `dist/**/*.js` and subagents' own `src/**/*.js`; subagents' entry and the web compiled bundle are additionally SHA-256 pinned before loading. These are fingerprints of this installed baseline, not a claim of full source audit or transitive-dependency integrity. Dependency trees are controlled installed inputs; a production release still needs reproducible dependency provenance. Alternate installations: `PI_GUI_SUBAGENTS_PACKAGE` and `PI_GUI_WEB_PACKAGE` (absolute package directories); defaults are `$HOME/.pi/agent/npm/node_modules/{pi-subagents,pi-web-access}`. Overrides must match the same reviewed versions/builds. Durable was initially absent. The user then explicitly authorized downloading it under `~/programs` and using it for this project. Reviewed Durable **1.1.0** is now installed at `~/programs/pi-gui-durable-1.1.0`; `PI_GUI_DURABLE_ROOT` selects an equivalent install root. `durable-lock.{mjs,json}` fingerprints the entire supplied artifact/dependency tree before loading; recorded installer manifest/lock are `durable-package{,-lock}.json`. Tests never install packages.

Each probe uses a disposable HOME, agent directory, XDG paths, session directory and working directory. Child environments are allowlisted rather than inherited: no provider keys, proxies, desktop buses, runtime hooks or parent session markers. Only the controlled fixture and project-owned Q+A extension load, except for disposable synthetic resource-discovery/configuration tests and explicitly loaded pinned subagents/web packages. Web probes use only SearXNG/direct HTTP against an owned literal-loopback listener; browser cookies, browser auto-open, cloning, curator commands and external fetch fallbacks are disabled. Subagent definitions explicitly select the fake model and either no extensions (foreground provider-inheritance probe) or only the fake provider. No injected child factories, package test-runner modules or replacement executors are used. Pi automatic network activity is disabled with offline mode; the fake provider performs no network calls. The configured-provider probe deliberately uses actual API transport only to its owned loopback service, with synthetic credentials. This configuration is not an OS sandbox or a general network firewall.

Owned child stdout/stderr are continuously drained. The probe client splits on LF (not Node readline), decodes chunked UTF-8, correlates responses by ID, imposes deadlines/record/frame/diagnostic retention limits and uses bounded shutdown escalation on its own child only. It is **test harness code, not the production Rust connector**.

### RPC — `scripts/pi-compat/tests/rpc.test.mjs`

- Real CLI accepts ID-bearing commands and supports concurrent correlated responses.
- Malformed JSON returns a parse failure; the process remains usable. Unknown commands return correlated failures.
- Streaming text containing U+2028, U+2029 and a multibyte character survives LF framing. Streaming updates omit cumulative message/partial snapshots; final text is queryable.
- Prompt acceptance has `disposition: started`; extension command handling has `handled`. Neither is a model-completion event.
- Busy steering/follow-up queues expose pending counts. `clear_queue` returns their contents; clearing before `abort` prevents their delivery.
- Follow-up work produces multiple assistant responses before a single `agent_settled`. The GUI must not use `agent_end` as settled/idle.
- A fake permanent provider failure after accepted prompting appears as a terminal assistant error, not failed acceptance.
- Owned-process SIGKILL and invalid-CLI-option startup exits surface as failures.
- Closing stdin while idle runs `session_shutdown`, preserves saved history, and exits normally. Reopening that session preserves identity/history without an `agent_start`.

Additional `lifecycle.test.mjs` proof: active-run stdin-close exits normally and persists shutdown without delivering queued follow-ups; production user-bash `abort_bash` and stdin-close terminate a controlled Node child/grandchild tree (recorded PID terminal/zombie checks); production transient retry emits `auto_retry_start/end`, preserves failed raw entries and settles only after recovery; manual compaction uses the real summarizer with the fake model and small synthetic retention settings. Model selection, available thinking levels, queue modes, rename, statistics and compaction map to exact supported RPC commands. A further actual-RPC probe pauses its stdout consumer for 200 ms while production user bash emits **1 MiB**. Resuming drains every correlated `bash_execution_update.delta`, returns a bounded final output and reads the complete private output artifact under sandbox `TMPDIR`. **Finding:** Pi's rolling-buffer final output can report `truncated:false` despite omitted earlier bytes and a full-output artifact; do not infer transcript completeness from that boolean. The presence of `fullOutputPath` and streamed/retained byte counts matters. This is a bounded representative backpressure/output probe, not an unbounded stress or memory-limit guarantee. Additional executed proof now covers a **1500-ms pause and 4 MiB**, lost acknowledgement after actual model dispatch, session switching with pending Q+A, correlated persistence failure and actual output-artifact write failure. Lost acceptance does not mean unexecuted work: saved history reopens without an automatic resend. `set_session_name` can return EISDIR while its in-memory name already changed; do not infer durable success or blindly retry a mutation. An unavailable disposable TMPDIR produces ENOTDIR on the production output stream and **crashes Pi**; a returned artifact path is not persistence proof. Every finite writer is checked terminal before storage removal. Still untested/unsupported: overflow/automatic compaction recovery, escaped/daemonized shell descendants and actual disk exhaustion; stale GUI attempt gating remains milestone 1. Harness retention now checks complete frames as well as partial framing: 2-MiB frame, 16-MiB cumulative record and 10,000-record limits. These are not chosen production transcript limits.

### Q+A — `extensions/pi-gui-qna.ts`

The installed global `qna-ui.ts` explicitly checks `ctx.mode !== "tui"` and otherwise uses `ctx.ui.custom()`. RPC cannot render that custom component. It was read but not modified or loaded by these probes.

The project-owned replacement exposes the same `ask_user` inputs and compatible result details. It uses `ctx.ui.select()` followed by `ctx.ui.input()` for custom answers. Numbered choices preserve duplicate-label identity; descriptions remain visible in the selection strings. It forwards the operation signal to dialogs.

Verified through model-issued calls in the actual CLI:

- listed choice with description, duplicate labels and one-based selected index;
- custom input, trimming and custom-answer result details;
- explicit cancel, blank custom answer, invalid response and no-options/custom-disabled cases;
- abort while waiting unblocks the run; a late response cannot answer a later request;
- a separate standard-dialog fixture with a timeout resolves without approval.

Decision: **retain RPC as the candidate execution boundary**. Standard dialogs suffice for this Q+A feasibility slice; no SDK host is justified by Q+A alone. This is a two-step compatibility path, not the final native single-panel Q+A design. Rendering, hidden-thread routing, attention badges and sound remain milestone-1 work.

Normal-config exclusion now has synthetic executed proof (`ownership.test.mjs`): a user-scope `extensions: ["-extensions/qna-ui.ts"]` excludes the original file **before startup**, while retaining another global extension, prompt template and skill; the project Q+A works and Pi leaves settings unchanged. This is not a GUI-scoped overlay implementation and did not modify the real global configuration. Before enabling the bridge in ordinary sessions, explicitly exclude every original `ask_user` registration while preserving other desired extensions; do not load both and rely on conflict resolution. The probes use `--no-extensions` plus explicit extensions, which is intentionally not the final normal-use configuration policy. No arbitrary TUI component compatibility is claimed.

Pi 1.1.0 resolves timed-out/aborted RPC dialogs internally but emits no separate dialog-dismissal record. Native UI ownership must retire pending dialogs when the owning tool ends, the attempt exits or a session changes; do not leave stale prompts visible or infer permission from timeout.

### pi-subagents — `scripts/pi-compat/tests/subagents.test.mjs`

Twenty-two actual-CLI tests load the installed 0.76.1 package, disposable Markdown agent definitions, and `fixtures/subagents-bridge.ts`. The bridge calls the documented process-local event RPC and forwards replies/lifecycle events as namespaced JSON inside supported RPC `extension_ui_request/notify` envelopes. It does not write stdout, parse TUI widgets or replace production execution. Fake-provider gates are file-controlled, abort-aware and bounded to 15 seconds. Tests use bounded observation deadlines, release only their own gates on failure, and wait for their recorded runners to exit (or become zombies awaiting OS reaping) before deleting storage. Observation polling is harness synchronization, not a model workflow.

#### Startup review and isolation

Reviewed entry/startup/shutdown code, config loading, upgrade notices, child-session factory, async runner launch and control inbox before the retained test configuration was run. Startup installs watchers, restores status/history, discovers agents, cleans retained artifacts, initializes supervisor/liveness bookkeeping, and can start configured schedules. Upgrade notices read the local changelog/version marker, not a remote release endpoint. Agent discovery may execute `npm root -g` for package discovery; this is not package installation. Optional external runners, host commands, worktree hooks, scheduled work, uploads and third-party provider registrations are not covered or permitted by these tests.

Every retained probe sets **`PI_SUBAGENTS_TEMP_ROOT`** and **`TMPDIR`** inside its sandbox, disables schedules, uses fresh context, chooses eager tool registration and keeps artifacts under its disposable session directory. HOME/XDG/agent/session roots and allowlisted environment remain isolated. The package's default temp root is per-UID, **not per-profile**: disposable HOME alone is insufficient. One initial reconnaissance run wrote its own UUID artifacts to that default root before this was discovered; its stopped, sandbox-attributed artifacts were removed by exact run identity, without touching other runs or processes. Do not copy that initial configuration. Offline mode remains no network sandbox; safety comes from reviewed startup/explicit resources and fake models, not a general firewall claim.

#### Structured interfaces and observed behavior

- Package event RPC version **1** advertises `ping`, `status`, `manage` (schedule-only allowlist), `spawn`, `steer`, `interrupt`, `stop`, `resume`, `cost`. `spawn` is async-only and routes through the package's normal executor. Tested methods: ping, spawn, status, stop. Other methods are source-inspected, not runtime-accepted here.
- `ping.capabilities.fleetStatus.version === 1`; status exposes bounded fleet display records and `asyncSnapshot` run/activity/nested projections. Fleet keys are opaque display keys, not run IDs. Snapshot caps/omissions and observation timestamps must remain visible; it is not an exhaustive transcript. Nested identities can appear at both step and run levels; do not count every projection as a distinct child.
- Real asynchronous children run in a detached Node runner, with a real SDK `AgentSession`; fake-model markers verify the selected provider/model and separate PID. Launch details report disabled ambient extensions and the explicit resolved extension projection. Foreground children run as real SDK sessions **inside the parent PID**, including provider inheritance with an empty extension list.
- Foreground progress carries `runId` and stable numeric result `index`. On parent abort, the child fake model receives cancellation and progress reaches exitCode 1/`Fixture aborted`. Pi's final aborted tool result has **empty details**: retain earlier structured progress identity, not just the final tool result.
- A foreground child with `tools: subagent` launches a genuine child-safe nested leaf. Final results expose parentRunId, depth, model, sessionFile and child state; parsed saved sessions contain actual child assistant messages. An async parent likewise exposes a live nested leaf through `asyncSnapshot`; stopping that top-level runner stops its same-runner leaf. This does not establish cancellation of separately detached nested async runners.
- Package-targeted `status` with `view: transcript, lines: 20` returns the assigned task while a child waits. This is the package-returned transcript interface, **not terminal scraping**. Child saved-session paths and JSONL history are exercised under disposable storage. Detach receipts may omit sessionFile until reconciliation.
- The bridge observes async-started, async-complete and process-terminal events. No raw `subagent:*` event automatically appears as a core RPC stdout record. The ready event can precede a later-loaded bridge's session context; capability discovery must also support explicit ping.
- Async lifecycle artifacts assert version **3**. A live parent observes runner close and publishes process-terminal `state: observed`. A dead parent cannot run its close callback: the completed orphan's status still has process-terminal **pending** in these probes. Logical `complete`/`stopped`, stop acceptance and process-terminal proof are different facts.
- The fake text response does not satisfy the package's default acceptance attestation. Some completed results report `acceptance.status: rejected`; execution completion is not task acceptance/approval. No host gates or verification commands were run.

#### Decisions and remaining subagent gates

**Retain CLI RPC; a small project-owned bridge is warranted** for native child observation/control. The documented event RPC avoids internal executors and direct imports of extension-private state. The probe's notification envelope proves transport feasibility only; it is not the final GUI protocol or a generic application event bus. Production work still needs a bounded/versioned schema, method allowlist, correlation/timeouts, session/attempt identity, snapshot reconciliation, late-event retirement and shutdown acknowledgements. Do not forward/log arbitrary package payloads: nested route capabilities and private control metadata must stay inside the trusted adapter; expose only the GUI's reviewed display/control projection. Startup must ping rather than depend solely on an event it may have missed.

**GUI exit cannot merely abort or close parent stdin.** Before normal shutdown, stop owned async runs through the package control seam, reconcile nested/retained work and wait for terminal/process proof. If ownership or proof is uncertain, report interrupted/uncertain work instead of claiming everything stopped. A normal exit controller and an abnormal-exit ownership strategy are still required by the approved product contract; killing just the parent is demonstrably insufficient. Do not use broad process-name/PID scraping or unrelated termination.

Source-inspected public exports: `background-work` provides process-local registration/reconciliation/listing **without a universal cancellation API**; `external-runs` v2 is **display-only**, explicitly leaving job ownership/control with the registering extension; `inspectors` registers plugins rather than providing a GUI history API; `delegation` provides separate structured request/update/response/cancel events; `control-channel` exposes the file-backed async stop request. None grants universal descendant ownership. These export contracts are reconnaissance, not executed third-party-provider acceptance.

New executed proof:

- Two simultaneously admitted async runs are explicitly stopped while the parent remains alive. Each reaches logical `stopped` **and** structured process-terminal `observed`; only then is stdin closed. Reopening the same session shows zero active fleet work, retained child transcripts, and no automatic model start.
- A nested `async:true` leaf has a **different runner PID**. Root stop propagates to it; its recorded PID becomes terminal/zombie **without releasing the fake gate**. An initial hypothesis that the root would finish while its leaf waited failed: the real package keeps this tested root running while separately detached nested work is live. The retained probe tests actual behavior, not that discarded hypothesis.
- After parent SIGKILL, reopening its same saved session can use public RPC `stop` for its retained runner. Logical stop and Linux recorded-PID terminal proof are verified. This is **recovery after reopening**, not automatic crash-time cleanup or proof that a new parent receives the original runner-close event.
- A real child calls `contact_supervisor`. Its parent receives a normal custom-message RPC event with request ID, run ID, reason, `expectsReply` and question body. A model-issued `subagent_supervisor` reply bound to that request releases the child. Native supervisor wake can itself start a parent turn. This is not a native UI approval or a universal permission grant.
- Failure cleanup now attempts package stop for owned live receipts before parent shutdown, releases only owned fake gates, and checks every gate-recorded PID (including separately detached leaves) before deleting storage. Supervisor requests also have a disposable bounded timeout.

Further executed proof:

- A live owned observer detects parent SIGKILL and invokes the package's declared public `./control-channel` export in a disposable Node process. `requestAsyncStop` writes the production control inbox; the detached runner stops and its recorded PID becomes terminal, **without reopening a Pi session**. This establishes a viable guardian control seam for an already-admitted receipt, not a shipped guardian. Later probes below execute guardian loss and frontend crash before receipt consumption. Exhaustive arbitrary descendant/provider cleanup remains unsupported.
- A fake model deliberately receives but ignores cancellation. Public RPC stop still returns `stopping` while that runner stays alive. The harness records its Linux start-time identity and verifies it before signaling **only that owned PID** with SIGKILL. The PID terminates, but package whole-run proof is **`unknown`, reason `writer-close-unverified`**, not `observed`: forced death bypasses orderly writer-close evidence. The initial expectation of `observed` failed; the retained probe asserts the real conservative result. A production exit path must retain interrupted/uncertain state and must not claim all nested tools/providers stopped merely because the runner PID died.

Further executed: attached-child stdin-close signals cancellation before exit; foreground detach finishes through the production executor and retained child history reopens without replay; supervisor expiry settles the finite child and rejects a stale targeted reply. Guardian crash/receipt evidence is detailed below. Full resume/steer/interrupt parity is not promised by the approved initial child-inspection scope; arbitrary provider/external-run ownership remains **unsupported**, not best-effort admission. Production snapshot omission handling, attempt gating and reproducible transitive dependencies remain implementation/release requirements.

Four actual-CLI probes load the package's declared compiled extension. Its manifest, source entry/session hooks, tool core, activation, curator lifecycle, extraction routing, config/cache paths, SSRF policy and clone cleanup were inspected before loading. Session startup restores stored results and clears prior pending fetch/curator/clone state; the retained configuration starts no browser, cookie lookup, external search or clone. Executed proof:

- Production SearXNG search with multiple queries, raw page fetching, stored result retrieval and structured source-check artifacts survive RPC framing. Tool result `details.searchId` is the search identifier; fetched content uses `details.responseId`. Retrieval requires `queryIndex` or `urlIndex`; callers must not assume the output-schema `responseId` is duplicated in search details.

Ordinary config can request these workflows, so startup must classify/surface unsupported selections rather than assume defaults are safe.

- Synthetic normal user resource discovery works with precise Q+A exclusion and preserves unrelated global resources/settings. ### Decision boundary and resumable checkpoint

**Milestone 0 is complete for its compatibility-proof scope.** Rows 1–6 establish conditional basic-thread feasibility; rows 7–8 now execute against the user-authorized pinned Durable artifact. This is not production GUI or coordinator acceptance. Production enforcement remains milestones 1–2, not claimed by passing fixtures. The normal-config reuse requirement and the stop-on-exit contract conflict for arbitrary extensions/background providers that can launch independently owned or remote work but offer only display/registration interfaces. The tested web/subagents cleanup seams do not establish a universal cancellation contract. Restricting admission to audited ownership-capable extensions/providers would be a product compatibility decision; silently doing that would narrow normal configuration reuse. Conversely, admitting unsupported owners would weaken the stop-on-exit promise. **User decision: refuse unsupported owners.** Preserve their configuration, but block launch with an explicit compatibility explanation until their ownership/control contract is audited.
